# 备份与恢复

备份包含**数据库、附件与非敏感设置**，格式为 ZIP 包（`.lifeassistant-backup`），包内附 SHA-256 校验清单。备份**不包含** AI API Key（密钥保存在 Windows 凭据管理器中，恢复后需重新填写）。

## 自动备份

- 在设置页「基础偏好」中配置：
  - **自动备份频率**：每天 / 每周 / 仅手动（默认每周）。
  - **备份保留份数**：超过保留数时，仅轮换已成功的定时备份；手动备份与恢复前备份不会被误删。
  - **自动备份目录**：留空表示使用数据目录内 `backups\` 文件夹。
- 自动备份由后台任务执行；服务启动时按上次成功时间排定下一次备份。

## 手动备份

设置页「本地数据」→「立即备份」即可生成一份手动备份；也可通过接口：

```
POST /api/v1/backups
```

## 恢复

1. 设置页「本地数据」→「从完整备份恢复」：输入 `.lifeassistant-backup` 文件路径，点击「恢复预检」。
2. 预检会校验：包格式与版本、清单文件数量、每个文件的 SHA-256、数据库完整性（quick_check 与外键）。
3. 预检通过后确认执行。恢复流程：
   - 先在缓存目录解压并校验；
   - **自动创建当前数据的恢复前备份**（类型 `PRE_RESTORE`）；
   - 短暂停止数据服务，原子替换数据库与附件目录；
   - 任一步骤失败都会**还原原目录**，当前数据不受影响。
4. 恢复后如果提示缺少 AI 凭据，请在 AI 设置中重新填写（API Key 不随备份保存）。

> 恢复会整体替换当前数据（回到备份时的状态）。恢复前请确认已理解这一点；系统会保留恢复前备份以便回退。

## 数据目录迁移

设置页「本地数据」→「迁移到新数据目录」：

1. 输入一个**新的空目录**并执行「迁移预检」（显示文件数与总大小）。
2. 确认后：停止写入 → 复制全部数据到暂存目录 → 校验数据库完整性 → 原子切换 → 原目录保留为回退副本。
3. 目标目录非空、与当前目录相同或互相嵌套都会被拒绝；任何失败都会保持原目录活动。

## 升级前备份

当数据目录来自旧版本（Schema 版本低于 12）时，服务启动会自动在 `backups\pre-migration-*.db` 生成升级前备份，之后才执行迁移。该备份是完整数据库副本，可用于升级失败时回退。

## 校验与故障注入保障

- 备份包损坏（校验和/文件缺失/格式不符）会在**触碰当前数据之前**被拒绝。
- 恢复包内数据库非法（即使校验和一致）也会在切换前被拒绝。
- 恢复切换后若迁移器无法打开新数据库，会自动回滚到原数据目录并保持应用可用。
- 上述行为均有自动化演练测试覆盖（见 `apps/server/test/m8-010-reliability.drill.test.ts`）。
